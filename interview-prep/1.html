What is ASP.NET Core Web API?

A practical, interview-ready explanation covering REST APIs, routing, controllers, dependency injection, middleware, model binding, validation, authentication, status codes, versioning, and a complete example.

Interview definition

ASP.NET Core Web API is a framework for building HTTP-based services and RESTful APIs using ASP.NET Core. It is cross-platform, high-performance, open-source, and designed to serve clients such as web applications, mobile apps, desktop applications and other services.

1. What is ASP.NET Core Web API?

Simple definition: ASP.NET Core Web API is a part of the ASP.NET Core platform used to create HTTP APIs that expose application functionality and data through endpoints such as GET, POST, PUT, and DELETE.

A Web API normally acts as the backend between a client and application/business logic. The client sends an HTTP request, the API processes it, communicates with services or a database, and returns an HTTP response—commonly JSON.

Cross-platform

In a well-designed enterprise application, the controller should generally remain thin. It receives the request, validates or delegates it, calls an application/service layer, and converts the result into an appropriate HTTP response.

Interview point: ASP.NET Core Web API is not the same thing as a database-access technology. Entity Framework Core, Dapper, or another data-access library can be used underneath the API, but they are separate concerns.

4. Complete Simple Web API Example

Step 1 — Create the project

dotnet new webapi -n ProductApi
cd ProductApi
dotnet run

Step 2 — Model

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}

Step 3 — Controller

using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private static readonly List<Product> Products =
    [
        new Product { Id = 1, Name = "Laptop", Price = 75000 },
        new Product { Id = 2, Name = "Monitor", Price = 18000 }
    ];

    [HttpGet]
    public ActionResult<IEnumerable<Product>> GetAll()
    {
        return Ok(Products);
    }

    [HttpGet("{id:int}")]
    public ActionResult<Product> GetById(int id)
    {
        var product = Products.FirstOrDefault(x => x.Id == id);

        if (product == null)
            return NotFound();

        return Ok(product);
    }

    [HttpPost]
    public ActionResult<Product> Create(Product product)
    {
        product.Id = Products.Count + 1;
        Products.Add(product);

        return CreatedAtAction(
            nameof(GetById),
            new { id = product.Id },
            product);
    }

    [HttpDelete("{id:int}")]
    public IActionResult Delete(int id)
    {
        var product = Products.FirstOrDefault(x => x.Id == id);

        if (product == null)
            return NotFound();

        Products.Remove(product);
        return NoContent();
    }
}

Example custom middleware

public class RequestTimingMiddleware
{
    private readonly RequestDelegate _next;

    public RequestTimingMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var start = DateTime.UtcNow;

        await _next(context);

        var elapsed = DateTime.UtcNow - start;
        Console.WriteLine(
            $"{context.Request.Path} took {elapsed.TotalMilliseconds} ms");
    }
}

It can be registered with app.UseMiddleware<RequestTimingMiddleware>().

6. Routing and Model Binding

Attribute routing

[ApiController]
[Route("api/[controller]")]
public class OrdersController : ControllerBase
{
    [HttpGet("{id:int}")]
    public IActionResult GetOrder(int id)
    {
        return Ok(new { OrderId = id });
    }
}

A request such as GET /api/orders/25 can bind 25 to the id parameter automatically.

Binding from different request locations

[HttpGet]
public IActionResult Search([FromQuery] string name)
{
    return Ok(name);
}

[HttpGet("{id}")]
public IActionResult Get([FromRoute] int id)
{
    return Ok(id);
}

[HttpPost]
public IActionResult Create([FromBody] Product product)
{
    return Ok(product);
}
Tip: With [ApiController], ASP.NET Core provides automatic API-focused behavior such as automatic HTTP 400 responses when model validation fails.

8. Dependency Injection Example

ASP.NET Core has built-in dependency injection. Instead of creating dependencies directly inside controllers, register services and inject abstractions. 

public interface IProductService
{
    IEnumerable<Product> GetProducts();
}

public class ProductService : IProductService
{
    public IEnumerable<Product> GetProducts()
    {
        return
        [
            new Product { Id = 1, Name = "Laptop", Price = 75000 }
        ];
    }
}
// Program.cs
builder.Services.AddScoped<IProductService, ProductService>();
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private readonly IProductService _service;

    public ProductsController(IProductService service)
    {
        _service = service;
    }

    [HttpGet]
    public IActionResult Get()
    {
        return Ok(_service.GetProducts());
    }
}

This improves separation of concerns and makes unit testing easier because a mock implementation can be supplied to the controller.

9. Authentication and Authorization

Web APIs frequently use JWT bearer authentication, OAuth/OpenID Connect, or another identity mechanism. Authentication determines who the caller is; authorization determines what that caller is allowed to do. 

[Authorize]
[HttpGet("admin")]
public IActionResult GetAdminData()
{
    return Ok(new { Message = "Only authorized users can access this." });
}

Role or policy-based authorization can further restrict endpoints. In production systems, authentication and authorization should be configured centrally rather than implemented manually in every controller.

11. Web API vs Minimal API

Modern ASP.NET Core also supports Minimal APIs. They allow endpoints to be defined with less ceremony and are useful for small services, microservices, and focused HTTP endpoints.

Controller-based API

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
        => Ok(new[] { "Laptop", "Monitor" });
}

Minimal API

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/api/products", () =>
    Results.Ok(new[] { "Laptop", "Monitor" }));

app.Run();
Interview point: Controller-based APIs and Minimal APIs are both ways of building HTTP APIs in ASP.NET Core. The choice depends on application size, conventions, team preferences, endpoint complexity, and architecture.

12. Enterprise Request Example

Consider an enterprise endpoint:

GET /api/vehicles/12345/status
  1. Client sends an HTTP request.
  2. Middleware handles cross-cutting concerns.
  3. Authentication verifies the caller.
  4. Authorization checks access.
  5. Routing selects the appropriate endpoint.
  6. Model binding converts route/query/body values into .NET objects.
  7. The controller delegates to an application service.
  8. The service applies business rules.
  9. A repository or data-access component retrieves data.
  10. The API returns a structured JSON response with an appropriate HTTP status code.
{
  "vehicleId": "12345",
  "status": "Active",
  "lastUpdated": "2026-08-16T18:30:00Z"
}

13. How to Answer in an Interview

Strong 30–45 second answer:

“ASP.NET Core Web API is a cross-platform, high-performance framework for building HTTP-based APIs and RESTful services using ASP.NET Core. It allows us to expose business functionality through endpoints such as GET, POST, PUT, and DELETE. It provides features such as routing, middleware, dependency injection, model binding, validation, authentication and authorization. APIs commonly return JSON and can be consumed by Angular, React, mobile applications or other backend services. In enterprise applications, controllers typically delegate business logic to services, which can then interact with repositories or databases.”

14. Key Takeaways

  • ASP.NET Core Web API is used to build HTTP APIs and backend services.
  • It is cross-platform and built on modern .NET.
  • It supports routing, middleware, dependency injection, model binding and validation.
  • It integrates naturally with authentication and authorization.
  • APIs commonly communicate using JSON over HTTP.
  • It can be implemented using controllers or Minimal APIs.
  • For enterprise systems, separating controllers, services, and data access improves maintainability.
